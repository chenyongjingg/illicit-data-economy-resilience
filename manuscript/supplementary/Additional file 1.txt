Supplementary Note S1.3 reports a census of the result artifacts this study
produced. This file carries the rule that draws the census boundary, so that the
number can be recomputed rather than taken on trust. It accompanies Supplementary
Additional file 2, which is the census itself.

## 1. The rule

A file is **in scope** if and only if both of the following hold.

1. **Path.** It lies under one of the ten directories listed in §3 below. All ten
   are subdirectories of `results/`, and they are exactly the directories that
   occur as path prefixes in the manifest — the scope was read off the manifest,
   not stipulated for it, so the two cannot disagree.
2. **Content.** It is a *result*: an output of a run of an analysis stage. A run's
   log is in scope, because the log is what makes that output checkable, and so is
   a superseded generation of a result. Raw inputs and scratch that no stage wrote
   as its own output are out of scope even when they live under a walked directory.

The **time point** of the census is the manifest's build. Artifacts produced
after it are not in it. This matters because the analysis continued after the
manifest was first written, and an artifact produced later would otherwise be
silently uncovered.

required: a forward check cannot see an unregistered file, and an unregistered

## 4. How to recompute

Place the `results/` tree (available from the corresponding author) and this
file's companion (`Additional file 2.txt`) in one directory, then run from that
root:

```
sha256sum -c "Additional file 2.txt"
wc -l "Additional file 2.txt"   # 302
```

A tree of the same name is not necessarily the right tree. The manifest's
paths are relative to the directory that contains `results/`, and the
`results/` it covers is the one holding exactly 196 files at its top level
together with the nine subdirectories of §3, 302 files in all. If every line
reports as missing, the tree is at the wrong depth; if a handful report as
missing or as mismatched, the tree has drifted and the census of Supplementary Note S1.3 no
longer describes it. The check was run again in both directions on
2026-10-07: 302 lines verified, no file present under the ten trees but
outside the manifest, and no manifest path absent from disk.

The second command is not redundant. `sha256sum -c` reports a mismatch or a
missing file; it cannot report a file that exists on disk but is absent from the
manifest. The count and the per-tree table above are what close that direction,
and they were produced by walking the ten trees and comparing the resulting path
set against the manifest's.

## 5. Earlier values, and why they changed

An earlier draft of Supplementary Note S1.3 reported **283** manifest entries and flagged six
de-leakage artifacts carried outside them. That
gap is closed rather than carried forward: the six de-leakage artifacts, the two
figures introduced in the protocol and negative-result sections, and the analysis table of the controlled-analyses section are all
registered, and no artifact in scope is unregistered. The figure of 302 and the
figure of 196 for the top-level tree are the two numbers Supplementary Note S1.3 now prints.

An earlier build of this file reported **294** entries and **188** files at the top
level of `results/`. It was rebuilt on 2026-10-07, after the eight outputs of the
four pre-registered L4 cells were added to the delivery tree: one JSON and one
plain-text result file per cell, all eight at the top level of `results/`. The nine
subdirectories of section 3 are unchanged, and the two-directional check of sections
2 and 4 was re-run on the rebuilt manifest.
